# 电商AI全员营销系统（AIMS）— 分层架构与数据流协作

> **版本**：v3.0（OpenClaw原生版）
> **基于**：《AI全员营销系统（AIMS）——项目方案（OpenClaw版）》+《AIMS架构与业务设计文档》
> **核心原则**：以OpenClaw为核心智能体引擎，6层原生架构，数据流驱动业务闭环

---

## 一、分层架构总览

### 1.1 六层架构全景

AIMS基于OpenClaw原生6层架构构建，每层职责清晰、接口标准化，数据在层间自上而下流转、自下而上反馈，形成完整的感知-决策-执行-记忆闭环。

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│  L1 通道层 (Channels)                                                                           │
│  飞书 · 企微 · 钉钉 · Telegram · WhatsApp · Discord                                              │
│  职责：多端IM交互入口，用户消息接入与Agent回复投递                                                  │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │ 消息上行 / 回复下行
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│  L2 网关层 (Gateway)                                                                            │
│  Token认证 · 会话管理 · Bindings路由 · 限流防护                                                   │
│  职责：统一流量入口，安全认证，消息路由分发到目标Agent                                               │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │ 路由消息
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│  L3 Agent层 (Agents)                                                                            │
│  main · ecommerce · social-media · cs · office                                                  │
│  职责：意图识别、任务拆解、置信度判断、人机协同决策、编排Skills与MCP                                 │
│  四模块：感知(Channels/Cron) → 决策(LLM/SOUL.md/置信度) → 执行(Skills/MCP) → 记忆(RAG)          │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │ Skill调用 / MCP工具调用
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│  L4 Skills层 + L5 MCP层                                                                         │
│                                                                                                  │
│  Skills技能系统（三级加载：元数据 → SKILL.md → 脚本/资源）                                         │
│  电商Skills · 社媒Skills · 通用Skills · 客服Skills · 办公Skills                                   │
│                                                                                                  │
│  MCP Server集群（四阶段：意图识别 → 能力协商 → 标准化调用 → 执行反馈）                              │
│  电商平台MCP · 社媒平台MCP · 多模态MCP · 数据服务MCP · ERP系统MCP                                 │
│                                                                                                  │
│  职责：确定性工具执行、外部API对接、数据库操作、向量检索                                            │
└──────────────────────────────────────┬───────────────────────────────────────────────────────────┘
                                       │ 读写数据
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│  L6 数据层 (Data)                                                                               │
│  MySQL 8.0 · Redis · Milvus · Qdrant · OSS/MinIO · Canal/Kettle/DataX                           │
│  职责：持久化存储、缓存加速、向量检索、对象存储、ETL数据回流                                        │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 分层职责与数据流方向

| 层级 | 核心职责 | 上行数据流（用户→数据） | 下行数据流（数据→用户） |
|------|----------|------------------------|------------------------|
| **L1 通道层** | IM消息接入与投递 | 用户消息 → Channels插件 → Gateway | Agent回复 → Channels插件 → 用户 |
| **L2 网关层** | 认证、路由、限流 | 认证通过 → Bindings路由 → 目标Agent | 路由结果 → 会话管理 → 通道投递 |
| **L3 Agent层** | 意图识别与决策编排 | 意图识别 → 任务拆解 → Skill/MCP调用 | 执行结果 → 置信度判断 → 回复生成 |
| **L4 Skills层** | 确定性工具执行 | Skill脚本 → MCP调用 → 数据读写 | 执行结果 → Agent反馈 |
| **L5 MCP层** | 外部能力对接 | MCP协议调用 → 外部API/数据库 | API响应 → MCP封装 → Skill返回 |
| **L6 数据层** | 存储与回流 | 写入业务数据/向量/缓存 | 查询结果/向量召回/缓存命中 |

## 二、层间数据流详解

### 2.1 L1→L2：消息接入与认证

```
用户（飞书/企微/钉钉/...）
  │
  │ ① 发送消息："帮我生成蓝牙耳机Listing"
  ▼
Channels插件（原生通道）
  │
  │ ② Webhook回调 / 长轮询
  ▼
Gateway
  ├─ Token认证（JWT/Bearer验证）
  ├─ 会话管理（创建/恢复session）
  ├─ Bindings路由（匹配Agent）
  └─ 限流防护（内置限流器）
```

**数据流要素**：

| 数据项 | 方向 | 格式 | 说明 |
|--------|------|------|------|
| 用户消息 | L1→L2 | OpenClaw Message | 包含channel、user_id、text、timestamp |
| 认证Token | L2内部 | JWT/Bearer | Gateway校验，v2026.3.7+强制 |
| 路由结果 | L2→L3 | Agent ID | Bindings匹配确定目标Agent |
| 会话上下文 | L2↔Redis | Session JSON | 会话状态缓存，per-channel隔离 |

### 2.2 L2→L3：路由分发与Agent感知

```
Gateway
  │
  │ ③ 路由到目标Agent
  ▼
main Agent（大总管）
  │
  │ ④ Bindings二次路由
  ├─→ ecommerce Agent（飞书"电商运营*"群组）
  ├─→ social-media Agent（飞书"社媒营销*"群组）
  ├─→ cs Agent（企业微信）
  └─→ office Agent（飞书"办公自动化*"群组）
```

**Bindings路由规则**：

| 路由条件 | 目标Agent | 匹配方式 |
|----------|-----------|----------|
| channel=feishu, group="电商运营*" | ecommerce | 通配符匹配 |
| channel=feishu, group="社媒营销*" | social-media | 通配符匹配 |
| channel=wework | cs | 全量匹配 |
| channel=feishu, group="办公自动化*" | office | 通配符匹配 |
| 其他 | main | 默认兜底 |

### 2.3 L3→L4/L5：决策编排与工具调用

Agent决策后，通过Skills和MCP两层执行具体操作：

```
Agent（决策模块）
  │
  │ ⑤ 意图匹配 → 选择Skill
  ▼
Skills层（三级加载）
  │
  │ ⑥ 第一级：元数据（名称+简介，Agent启动时已加载）
  │ ⑦ 第二级：SKILL.md（任务匹配时加载核心指令）
  │ ⑧ 第三级：脚本+资源（执行阶段按需加载）
  ▼
Skill脚本执行
  │
  │ ⑨ 需要外部数据 → 调用MCP
  ▼
MCP层（四阶段机制）
  ├─ 意图识别：确定需要哪种外部能力
  ├─ 能力协商：查询MCP Server工具列表
  ├─ 标准化调用：按MCP协议构造请求
  └─ 执行反馈：返回结果或异常
```

**Agent→Skills调用映射**：

| Agent | 触发场景 | 调用Skills | 涉及MCP |
|-------|----------|------------|---------|
| ecommerce | Listing生成 | listing-gen + humanizer + 合规Skill | milvus-mcp, taobao-mcp |
| ecommerce | 广告优化 | ad-optimizer | mysql-mcp, taobao-mcp |
| ecommerce | 评论管理 | review-mgr | milvus-mcp, taobao-mcp |
| ecommerce | 素材生成 | material-gen + nano-banana-pro | dall-e-mcp |
| ecommerce | 数据报表 | report-gen + excel-viz | mysql-mcp, quickchart |
| social-media | 小红书种草 | xhs-seed + humanizer | qdrant-mcp, xhs-mcp |
| social-media | 抖音运营 | douyin-ops | qdrant-mcp, douyin-mcp |
| social-media | 视频号 | video-channel | qdrant-mcp, wechat-mcp |
| social-media | 舆情监控 | opinion-watch | qdrant-mcp |
| social-media | 私域导流 | cross-drain | wechat-mcp |
| cs | 订单查询 | order-query | mysql-mcp |
| cs | 物流跟踪 | logistics-track | 物流API MCP |
| cs | 售后处理 | after-sale | mysql-mcp, milvus-mcp |
| office | 周报生成 | report-gen | mysql-mcp, feishu-doc |
| office | Excel可视化 | excel-viz | quickchart, excel-mcp |
| office | 邮件处理 | email-mgr | 邮件API MCP |
| office | 文档自动化 | doc-auto | feishu-doc |

### 2.4 L4/L5→L6：数据读写与存储

```
Skills/MCP执行
  │
  ├── 写入数据 ──→ MySQL（业务数据：订单/商品/内容记录）
  │             ──→ Redis（缓存：会话上下文/Token/限流计数）
  │             ──→ Milvus（电商向量：商品/规则/售后知识）
  │             ──→ Qdrant（社媒向量：规则/话术/行业知识）
  │             ──→ OSS/MinIO（多模态素材：图片/视频/报表）
  │
  └── 读取数据 ←── MySQL（查询业务数据）
                ←── Redis（缓存命中）
                ←── Milvus（RAG向量召回）
                ←── Qdrant（RAG向量召回）
                ←── OSS/MinIO（素材下载）
```

**数据层读写矩阵**：

| 数据存储 | 写入场景 | 读取场景 | MCP Server | 频率 |
|----------|----------|----------|------------|------|
| MySQL | 会话记录、商品信息、订单数据、内容记录、定时任务 | 订单查询、数据报表、商品检索 | mysql-mcp | 高频 |
| Redis | 会话上下文、Token缓存、限流计数 | 上下文恢复、Token校验、限流判断 | redis-mcp | 极高频 |
| Milvus | 电商规则向量、商品向量、售后知识向量 | RAG电商规则召回、商品知识检索 | milvus-mcp | 中频 |
| Qdrant | 社媒规则向量、话术向量、行业知识向量 | RAG社媒规则召回、话术检索 | qdrant-mcp | 中频 |
| OSS | AI生成图片、报表文件、素材文件 | 素材下载、报表分发 | filesystem MCP | 低频 |

### 3.2 小红书种草笔记数据流

```
用户消息 → L1飞书 → L2 Gateway → L3 social-media Agent
  → L4 xhs-seed Skill → L5 qdrant-mcp → L6 Qdrant
  （检索小红书内容规则+爆款笔记参考+禁忌词）
```

**与Listing数据流的差异**：

| 维度 | Listing数据流 | 小红书种草数据流 |
|------|---------------|------------------|
| 目标Agent | ecommerce | social-media |
| RAG引擎 | Milvus（电商向量） | Qdrant（社媒向量） |

### 3.3 客服自动回复数据流

```
客户消息 → L1企微 → L2 Gateway → L3 cs Agent
  → 意图识别（售前/订单/物流/售后/投诉）
  → 情感判断（正面/中性/负面）
  ├── 置信度≥90% → L4 order-query/logistics-track/after-sale
  │                 → L5 mysql-mcp/物流API MCP → L6 MySQL
  │                 → 生成人性化回复 → 自动发送
  ├── 置信度60%-90% → 执行并通知客服人员
  └── 置信度<60% → 转人工（负面情感自动转人工）
```

**客服数据流特殊机制**：

| 机制 | 说明 | 数据流影响 |
|------|------|------------|
| 情感识别 | 对客户消息进行情感分析 | 负面情感→跳过自动回复→转人工 |
| 置信度门控 | 根据回复置信度分级处理 | 低置信度→人工确认→阻止自动发送 |
| 知识库联动 | 售后FAQ从Milvus召回 | RAG检索→模板匹配→个性化填充 |
| 用户画像 | 记录用户历史偏好 | Redis缓存→后续对话个性化 |

## 四、跨层协作机制

### 4.1 Agent四模块跨层协作

每个Agent的四大模块（感知-决策-执行-记忆）横跨6层架构，形成完整的闭环：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Agent四模块跨层协作                                   │
│                                                                             │
│  感知模块（Perception）                                                      │
│  ├─ L1 Channels：接收用户消息、多模态输入                                    │
│  ├─ L2 Gateway：Cron定时触发、事件监听                                       │
│  └─ L5 MCP：外部事件回调（如新评论通知）                                     │
│          │                                                                  │
│          ▼                                                                  │
│  决策模块（Decision）                                                        │
│  ├─ L3 Agent核心：LLM推理意图                                               │
│  ├─ L3 SOUL.md：人设规则约束                                                │
│  ├─ L3 置信度判断：自动/半自动/人工分级                                      │
│  └─ L6 RAG：知识库检索辅助决策                                               │
│          │                                                                  │
│          ▼                                                                  │
│  执行模块（Execution）                                                       │
│  ├─ L4 Skills：确定性工具脚本执行                                            │
│  ├─ L5 MCP：外部API调用、数据库操作                                          │
│  └─ L4 门控：高风险操作人工确认                                              │
│          │                                                                  │
│          ▼                                                                  │
│  记忆模块（Memory）                                                          │
│  ├─ 短期记忆：L2 Redis会话上下文                                             │
│  ├─ 长期记忆：L6 MySQL业务数据                                               │
│  └─ 向量记忆：L6 Milvus/Qdrant知识库                                         │
│          │                                                                  │
│          └──── 反馈闭环 ────→ 感知模块（下一轮交互）                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 RAG双引擎跨层协作

```
│  L6 数据层                                                                  │
│  ├─ .env不入库（敏感配置加入.gitignore）                                     │
│  ├─ API Key定期轮换（建议每90天）                                            │
│  └─ 网络隔离（默认绑定127.0.0.1，远程用Tailscale）                           │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.2 内容合规数据流

```
用户请求 → L1 → L2 → L3 Agent决策
  → L4 Skill生成内容
  → L4 合规检测Skill（敏感词+极限词+平台规则）
  ├── 合规通过 → L3 置信度判断
  │   ├── ≥90% → 自动输出 → L2 → L1 → 用户
  │   ├── 60%-90% → 执行并通知 → L2 → L1 → 用户+运营
  │   └── <60% → 人工审核 → 等待确认 → L2 → L1 → 用户
  └── 合规未通过 → 人工审核 → 修改后重新检测
```

## 十、端到端数据流总览

### 10.1 完整请求-响应数据流

```
用户请求 → L1 Channels → L2 Gateway（认证+路由）→ L3 Agent（意图识别+决策）
  → L6 RAG检索（Milvus/Qdrant，通过L5 MCP）
  → L4 Skill执行（三级加载+门控检查）
  → L5 MCP调用（外部API/数据库，四阶段机制）
  → L6 数据读写（MySQL/Redis/Milvus/Qdrant/OSS）
  → L4 结果处理（humanizer润色+合规检测）
  → L3 置信度判断（自动/通知/人工）
  → L2 会话管理 → L1 Channels投递 → 用户
```

### 10.2 数据流分层汇总

| 数据流类型 | 涉及层级 | 关键路径 | 典型延迟 |
|-----------|----------|----------|----------|
| 用户消息上行 | L1→L2→L3 | Channels→Gateway→Agent | <100ms |
| RAG知识检索 | L3→L5→L6→L3 | Agent→MCP→Milvus/Qdrant→Agent | 200-500ms |
| Skill工具执行 | L3→L4→L5→L6 | Agent→Skill→MCP→DB | 500ms-3s |
| LLM内容生成 | L3/L4内部 | Agent/Skill→LLM API | 1-5s |
| 合规检测 | L4内部 | Skill→合规Skill→RAG | 200-500ms |
| 回复下行 | L3→L2→L1 | Agent→Gateway→Channels | <100ms |
| Cron定时触发 | L3→L4→L5→L6→L1 | Cron→Agent→Skill→MCP→DB→deliver | 5-30s |
| ERP闭环执行 | L3→L5→ERP→L5→L6 | Agent→MCP→SCM/WMS/OMS→CDC→DB | 分钟级 |
| 数据回流ETL | ERP→L6 | Canal/DataX/Kettle→MySQL/Milvus/Qdrant | 分钟-小时级 |
| 自进化飞轮 | L6→L3→L4→L5→L6 | 知识库→Agent→Skill→MCP→数据更新 | 日/周/月级 |
